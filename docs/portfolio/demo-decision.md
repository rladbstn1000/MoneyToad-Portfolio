# 공개 체험을 프런트엔드 전용으로 분리한 이유

## 목적

공개 링크의 목적은 방문자가 돈꺼비의 장독대, 소비 내역, 조언, 곳간과 정보 입력을 빠르게 둘러보는 것이다. 실제 인증·DB·Redis 구현은 별도의 서버 연동 모드와 코드·검증 자료로 설명한다.

## 확인한 제약

[10단계의 자원 제한 시험](../deployment/10-demo-capacity-cleanup.md)에서는 Mac의 로컬 Docker에 512MiB·0.1 CPU를 제한했을 때 준비 완료까지 354.250초가 관측됐다. 당시 FE의 준비 대기 한도는 240초였다. 이는 TiDB·Upstash 지연을 포함하지 않는 로컬 시험이며 **실제 Render의 준비 시간으로 바꾸어 인용하지 않는다.**

서버 연동을 유지하면 방문자가 화면 체험 전에 준비·인증·데이터 요청을 거쳐야 한다. 이번 공개 체험에서는 서버의 상시 기동보다 접근 즉시 화면과 상호작용을 확인할 수 있는 방식을 선택했다.

## 선택

Cloudflare는 정적 파일을 제공하고, React 앱은 직접 작성한 샘플 거래·예산을 브라우저 메모리에 준비한다. 예산·분류 변경은 공통 상태와 계산에서 장독대·Chart·조언에 함께 반영한다.

같은 탭의 내부 이동에서는 변경을 유지한다. 새로고침·처음부터 다시하기·체험 종료 시 초기 샘플로 돌아간다. 개인정보나 금융정보를 입력받지 않으며 실시간 AI를 호출하지 않는다.

현재 공개 체험과 서버 연동은 명시적인 모드로 분리한다. 서버 장애 시 몰래 샘플 데이터로 전환하거나 가짜 인증 토큰으로 기존 인증을 통과시키는 방식은 사용하지 않는다. [구현과 수명 계약](../deployment/25-local-demo-and-wide-layout.md)

## 얻은 것과 남긴 것

공개 여정에서 서버 API 요청 없이 6개 화면·즉시 재집계·초기화가 동작함을 확인했다. 이는 백엔드 대기 경로를 제거한 결과이지, 최초 정적 파일 다운로드까지 0초라는 보장이 아니다. [공개 검증](../deployment/frontend-only-public-verified.md)

실제 API·JWT·Redis·SQL 구현과 [서버 연동 공개 검증](../deployment/public-full-experience-verified.md)은 보존한다. 정적 체험의 성공을 현재 서비스에서 DB 쓰기나 Redis 회전을 수행한 증거로 사용하지 않는다.

로컬 준비 354초와 로컬 UI 조작 약 64ms는 환경과 측정 시작·종료 지점이 다르다. 두 값을 나누어 성능 개선 배수를 만들지 않는다. [각 로컬 측정의 조건](../deployment/25-local-demo-and-wide-layout.md)
